# Curriculum card generation

You are replenishing a file-based daily technical-learning curriculum. Read `AGENTS.md` first and obey it.

The dynamic context appears below this template. Create exactly the requested number of cards, one for each listed `(stream, date, sequence)` slot, under the category directories in `cards/`. Copy the assigned `sequence`, `stream`, and `required_difficulty` exactly. Teach prerequisites before dependent concepts: beginner establishes vocabulary and safe basic workflows; intermediate applies them in realistic troubleshooting; advanced teaches tradeoffs, failure modes, security, performance, and operational judgment. A review may test only earlier sequence numbers. Use only categories allowed by the stream. Do not overwrite files. Each card must be approved, atomic, practical, accurate JSON matching `cards/schema.json`, and comfortably under Discord's limits when rendered. Prefer meaningful operational knowledge over trivia. Use only active card files plus the supplied topic/recent-card indexes for duplicate detection. Deleted Git history is intentionally out of scope: do not run `git status`, `git log`, or `git show`, and do not inspect deleted cards. Read the schema/instructions once, then begin writing promptly.

Use `language: bilingual`; read `state/terminology.json`; and write complete comprehension-first `content.en` and `content.my` blocks. This is a mini-lesson, not a source summary. Each block requires `title`, one atomic `learning_objective`, a concrete `simple_explanation`, cause-and-effect `how_it_works`, `visual`, realistic `use_case`, observable `expected_result`, interpretive `what_to_notice`, genuine `common_mistake`, `practical_tip`, aligned `question`, and concise `answer`.

Draft and fact-check English first. Start from a familiar situation, define new terms before relying on them, and use short sentences. Then explain the same meaning independently in natural Burmese as a patient technical instructor; do not copy English sentence structure. Retain and explain familiar English technical terms according to the terminology guide. The example must give the learner something concrete to run, inspect, compare, or predict. `expected_result` states what happens; `what_to_notice` explains why that result matters. Do not repeat one paragraph under different headings.

The visual must teach the core relationship at a glance. Prefer a 2–6 line flow, state transition, comparison, hierarchy, or annotated command. No line may exceed 48 characters; prefer a vertical mobile layout over a wide horizontal flow. Keep the complete rendered description below 2,700 characters per language. Depth must come from reasoning and interpretation, not padding.

Follow the date rotation as a quality-oriented guide. Update `state/topics.json` for every new curriculum card. Do not change scripts, prompts, workflows, documentation, systemd files, source files, imported cards, or existing cards. Run `python scripts/validate_cards.py` and fix only the cards/state you just created until it passes.
