# Source-derived candidate generation

Read `AGENTS.md` first. Analyze the normalized source referenced in the dynamic context. Select the highest-value knowledge for active recall; do not merely summarize or convert every paragraph/cell. Generate no more than the card budget, and fewer when the source does not support enough excellent atomic cards.

Write separate JSON card files only inside the exact output directory. Each must match `cards/schema.json`, use `language: bilingual`, and put the complete learning content in `content.en` and `content.my`. Draft and fact-check the English version first. Then write Burmese from the understood meaning—not by substituting words sentence-by-sentence. Preserve commands, code, flags, filenames, acronyms, and established technical terms in English when translation would reduce precision. Both languages must teach the same claim but should read naturally in their own language.

Make every card substantial but atomic. Both language blocks require `title`, `summary`, `explanation`, `how_it_works`, `visual`, `use_case`, `common_mistake`, `practical_tip`, `question`, and `answer`; add `expected_result` when an example produces interpretable output. Explain new terms before relying on them, use short cause-and-effect steps, connect the idea to a realistic scenario, and tell the learner what to notice in the example. The `visual` must be a compact 2–6 line text flow, state transition, comparison, hierarchy, or annotated command that materially improves understanding and remains readable on a phone. Do not pad with repetition, generic encouragement, decorative diagrams, or giant tutorials. Aim for roughly 650–1,050 instructional characters in English and 600–1,250 in Burmese before code and visual.

Use `status: candidate`, be undated, choose the best fitting configured `stream` and one of its allowed categories, set `generated_from_source: true`, include the supplied `source_type`, `source_file`, `source_title`, and priority, and retain only source section/page/cell metadata that is directly supported by markers in the normalized text. Do not invent references or claims. Set `needs_review: true` when grounding is uncertain. Use the supplied existing-card index for duplicate avoidance; do not reread every existing card unless a specific possible duplicate requires comparison. Never modify the source or any other repository file.

Depth meaning: quick selects only central ideas; normal balances central concepts and implementation knowledge; deep adds justified detail without sacrificing atomicity. Run validation on your output directory and correct your new files until it passes.
